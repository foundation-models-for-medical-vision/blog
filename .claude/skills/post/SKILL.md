# Blog Post Helper

Create a new blog post or get answers about writing blog content in this project.

## Determine User Intent

First, **recursively search the `drafts/` directory** (including all subdirectories) for `.md` files:

- If there is **exactly one `.md` file** → go to [Publish Draft](#publish-draft) using that file.
- If there are **multiple `.md` files** → list them (showing their relative paths from `drafts/`) and ask the user which one to publish.
- If there are **no `.md` files** in `drafts/` or its subdirectories, then:
  - Tell the user: "The `drafts/` directory does not contain any `.md` files. Would you like to create a new blog post?"
  - If they confirm → go to [Create New Post](#create-new-post)
  - If they asked a **question about blog writing** → read `.claude/skills/post/faq.md` and answer based on its content. If their question isn't covered there, read the relevant source files to find the answer.

## Create New Post

1. If the user hasn't provided a title, ask only for the **Title**. All other fields use defaults:
   - **Date**: today (YYYY-MM-DD)
   - **Tags**: `[]`
   - **Draft**: `false`
   - **Summary**: `''`
   - **Authors**: `['junma']`

2. Generate the slug from the title (lowercase, hyphens, no special characters).

3. Extract the year and month (two-digit, e.g. `04`) from the date.

4. Create the MDX file at `data/blog/{year}/{month}/{slug}.mdx` with this template:

```mdx
---
title: '{title}'
date: '{date}'
tags: []
draft: false
summary: ''
authors: ['junma']
---

Start writing here...
```

5. Create the image directory at `public/static/images/{year}/{month}/{slug}/`.

6. **Sync authors**: For any author in the `authors` list without a matching file in `data/authors/`, ask the user whether they want to create the author file. If yes, ask for display name and short bio, then create it using the template in Publish Draft step 9. If no, ask the user to pick from existing authors or provide a different slug.

   > **Note:** `app/tag-data.json` is auto-generated by Contentlayer during the build. Do NOT manually edit it.

7. After creating the file, briefly confirm and remind the user:
   - The file path and post URL
   - Images go in `public/static/images/{year}/{month}/{slug}/`
   - They can continue to ask you to modify the post (add tags, summary, content, etc.) or edit the file directly

## Publish Draft

Publish a `.md` file from `drafts/` as a blog post.

### Draft Directory Layout

The `.md` file may be at the top level of `drafts/` or nested in subdirectories:

```
drafts/
  my-article.md              # Top-level draft
  image1.png                 # Images alongside the .md file
  subdir/deeper/
    another-article.md        # Nested draft
    figure.jpg                # Images alongside the nested .md file
```

Images may be in the **same directory** as the `.md` file or in subdirectories alongside it.

### Steps

1. **Read the `.md` file** from `drafts/` and parse its content.

2. **Pre-check: validate required files and information.** Before any processing, analyze the draft and report what is ready and what is missing. Present a checklist to the user:

   - **Frontmatter fields**: Only **`title`** and **`authors`** require user confirmation. All other fields (`date`, `tags`, `summary`) are optional: if missing, use defaults silently (date → today, tags → `[]`, summary → auto-generated) without asking.
   - **Title** (required): Use frontmatter `title` if present. If missing, derive from the H1 heading or filename.
   - **Authors** (required): Use frontmatter `authors` if present. If missing, check `data/authors/` for existing author files. If there is exactly one author file, use that author. If there are multiple, list them and ask the user to pick. If there are none, ask the user to provide a new author's slug. For any explicitly listed author with no matching file in `data/authors/`, **ask the user whether they want to create the author file**. If yes, ask for the author's display name and short bio, then create the file using the template in step 9. If no, ask the user to pick from existing authors or provide a different author slug.
   - **Images**: Scan the content for image references (`![...](...)`, `src="..."`, etc.). For each referenced image, check whether the file exists relative to the `.md` file's directory. Report any missing image files.
   - **Bibliography**: If the content contains citations (`[@...]`), check whether a `bibliography` field is set in frontmatter and the referenced `.bib` file exists.

   **Present the proposed frontmatter** as a fenced YAML block (title, date, tags, summary placeholder, authors) along with any warnings (missing images, bibliography issues). If everything looks complete and there are no warnings, proceed automatically. If there are warnings or missing required fields, **wait for user confirmation** before proceeding.

3. **Derive the slug** from the `.md` filename (strip extension, lowercase, hyphens, no special characters).

4. **Finalize frontmatter.** Use the frontmatter confirmed in step 2. Fill in any remaining missing fields with defaults: `date` → today, `tags` → `[]`, `draft` → `false`, `summary` → auto-generate a concise 1–2 sentence summary from the post content.

5. **Determine the year and month** (two-digit, e.g. `04`) from the `date` field.

6. **Copy images.** Collect all image files referenced in the content by resolving their paths relative to the `.md` file's directory. Also find any image files (`*.png`, `*.jpg`, `*.jpeg`, `*.gif`, `*.webp`, `*.svg`) in the same directory and subdirectories as the `.md` file. Copy all found images to `public/static/images/{year}/{month}/{slug}/`, preserving the relative directory structure from the `.md` file's directory.

7. **Rewrite image paths** in the content. Replace relative image references with the canonical blog path `/static/images/{year}/{month}/{slug}/{relative-path}` (preserve subdirectory structure). Handle:
   - `./image.png`, `image.png`, `images/fig.png`, `../image.png` (relative paths)
   - Markdown syntax: `![alt](path)`
   - HTML/JSX syntax: `src="path"` or `src={...}`

8. **Write the `.mdx` file** to `data/blog/{year}/{month}/{slug}.mdx` with the final frontmatter + rewritten content.

9. **Create missing author files.** For each missing author identified in step 2 (user already provided display name and bio), create `data/authors/{author}.mdx` with this template:
     ```mdx
     ---
     name: '{display name}'
     avatar: ''
     occupation: ''
     company: ''
     email: ''
     x: ''
     linkedin: ''
     github: ''
     ---

     {short bio}
     ```

   > **Note:** `app/tag-data.json` is auto-generated by Contentlayer during the build. Do NOT manually edit it.

10. **Content verification.** Validate the generated `.mdx` file without running a full production build:
    - Check that the YAML frontmatter parses correctly (valid YAML, required fields present).
    - Check that all image paths referenced in the content exist under `public/`.
    - Check that there are no obvious MDX syntax errors (unmatched JSX tags, invalid imports).
    - If any issues are found, fix them and re-check. Do NOT proceed until all checks pass.

11. **Keep the original files.** Do NOT delete the `.md` file or images from `drafts/`. The user may want to keep originals for reference.

12. **Print the generated file tree** so the user can see what was created. Use a tree-style listing showing all new/modified paths, for example:
    ```
    data/blog/2026/04/my-article.mdx
    public/static/images/2026/04/my-article/
    ├── image1.png
    └── image2.jpg
    ```

13. **Show a summary** to the user:
    - The final frontmatter values (title, date, tags, summary)
    - Post URL (`/blog/{year}/{month}/{slug}`)
    - Content verification result (passed)

14. **Ask the user to confirm** before committing. Wait for explicit approval, then commit and push.
